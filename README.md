# Steppe Climate ML

Код курсовой по анализу суточной амплитуды температуры (DTR) и месячных осадков в степной зоне России. Проект сопоставляет ряды метеостанций с сеточными данными CRU TS, оценивает прогнозы Random Forest, KNN и MLP и формирует карты и отчёты.

## Структура

- [`code/kursach011.py`](code/kursach011.py) — основная точка входа для подготовки данных, прогнозирования, валидации и визуализации.
- [`code/kursach011_modules/`](code/kursach011_modules/) — загрузчики Meteostat и CRU TS, расчёт прогнозов, подбор параметров и построение карт.
- [`code/`](code/) — дополнительные скрипты для LSTM, EOF/PCA, корреляционного анализа и подготовки отчётов.

| `meteo_ru/daily_sources.csv` | Исходные флаги `tmin_flag`, `tavg_flag`, `tmax_flag` и `prcp_flag` для каждой станции и даты из суточного TXT. |
| `meteo_ru/daily_source_summary.csv` | Годовые числа и доли модельных суточных осадков и DTR по флагам Meteostat. |
| `cru ceda/4.10/cru_aligned_data.csv` | Рабочие месячные ряды CRU TS 4.10 в точках станций за 1901–2025 годы. |
| `cru ceda/4.06/`, `cru ceda/4.06-reproduced/` | Эталон и воспроизведённая выгрузка CRU TS 4.06 за 1901–2020 годы. |
| `maps_countries/`, `maps_ecoregions/`, `maps_relief/` | Границы стран, экорегионы и рельеф для геообработки и построения карт. |

Данные и сгенерированные результаты хранятся локально. Правила исключения описаны в [`.gitignore`](.gitignore).

Рабочий ряд METEO_RU включает наблюдения и модельные оценки. Загрузчик запрашивает `model=True, flags=True`. Сводка считает модельным по классификации Meteostat значение с флагом, содержащим `G`. Для DTR учитываются оба экстремума, и достаточно `G` у одного из них. Meteostat 1.7.6 также использует `G` для кодов источника, которых нет в словаре библиотеки. Доля `ModeledSharePct` рассчитывается от всех доступных значений показателя, в том числе значений без флага. Они учитываются в отдельной графе `Unknown`. При сохранении загрузчик выводит общий итог в консоль.


## Подготовка CRU TS 4.10

С установленными зависимостями и сохранённым `meteo_ru/stations_coords.txt` выполни из корня проекта.

```console
python code/prepare_cru.py
```

Скрипт скачивает архивы DTR и осадков по HTTPS, вырезает регион и собирает станционный CSV. Срез содержит 1 500 месяцев с января 1901-го по декабрь 2025-го. Центры ячеек лежат между 41,25 и 59,75° с. ш. и между 28,25 и 124,75° в. д. с шагом 0,5°. В каждом NetCDF сохранена его переменная `stn` с числом станций, участвовавших в интерполяции. [Официальный архив CRU TS 4.10](https://crudata.uea.ac.uk/cru/data/hrg/cru_ts_4.10/)

Результаты записываются в `cru ceda/4.10/`. Файл `station_grid.csv` содержит WMO, координаты станции и координаты выбранной ячейки. В `source.json` записаны версия, URL, период, границы и команда. При повторном запуске региональные NetCDF берутся из кэша. Если региональные файлы отсутствуют, скрипт вырежет срез из сохранённых `.gz` в `archives/`.

CRU TS строит сеточные ряды с использованием станционных наблюдений. Совпадение с Meteostat само по себе не подтверждает независимую точность. [Метод CRU TS](https://crudata.uea.ac.uk/cru/data/hrg/gefaq2.htm)

## Запуск

Корень проекта определяется по расположению Python-файлов. Пути к данным и результатам вычисляются относительно этого корня, поэтому скрипты можно вызывать из другой рабочей папки, указав путь к скрипту.

Команды ниже выполняются из корня проекта в Python-окружении с установленными зависимостями.

```console
python code/kursach011.py
```

Основной сценарий готовит отсутствующие таблицы, обучает модели и строит карты. Для CRU и METEO_RU используются два режима.

| Режим | Период оценки | Горизонт | Переобучение |
| --- | --- | --- | --- |
| Стандартный прогноз | 2024 | Следующий месяц | Ежемесячно |
| Долгосрочная валидация | 1990–2020 | Январь–декабрь из одной точки выпуска | Ежегодно |

При повторном запуске RF, KNN и MLP используют готовые CSV, если совпадают хеши входных данных, кода расчёта и рабочих параметров. Для METEO_RU в хеш данных входят суточные ряды и координаты станций, для CRU — станционный CSV. Изменение входного файла вызывает пересчёт для соответствующего источника. Старые CSV без хешей пересчитываются при первом запуске. Скрипт выводит причину пересчёта рядом с именем файла.

Чтобы принудительно пересчитать прогноз и валидацию с текущими параметрами, запусти:

```console
python code/kursach011.py --force
```

После изменения данных или кода запусти основной сценарий перед отдельными скриптами аналитики, EOF и корреляции. Они читают сохранённые CSV валидации.

Рядом с каждым новым CSV помесячного прогноза и годовой валидации сохраняется JSON с тем же именем, например `CRU_CEDA_DTR_2024.json`. Это относится к основному сценарию RF, KNN и MLP и к отдельному сценарию LSTM. В JSON записаны дата и время расчёта (UTC), набор данных, контрольные суммы входных файлов, версия CRU и фактически применённые настройки моделей, включая seed, где он используется.

Для каждого выполненного обучения JSON показывает месяц выпуска, границы периода целевых значений и число обучающих примеров. В помесячном режиме пример соответствует паре «станция — месяц», в годовом — паре «станция — год» с 12 целевыми значениями. Месяцы с доступными парами «прогноз — факт» указаны отдельно для каждой модели. Если конечный год валидации не задан, поле `requested_end_month` содержит `null`.

При повторном использовании CSV основной сценарий сохраняет исходный JSON. Если JSON отсутствует, повреждён или его `csv_sha256` не совпадает с CSV, прогноз рассчитывается заново. Чтобы сравнить два расчёта, сохрани первую пару CSV и JSON в отдельную папку до следующего пересчёта.

Зимние карты и отдельный региональный график за расчётный 2024 год используют декабрь 2023, январь и февраль 2024. Основной сценарий сохраняет прогноз на декабрь 2023 в отдельном CSV. Годовой CSV и график стандартного прогноза охватывают январь–декабрь 2024. На зимних картах и графике указан точный период, а в именах файлов есть диапазон `2023-2024`. Если у модели нет прогнозных строк за один из зимних месяцев, её карты и линия на зимнем графике пропускаются.

В долгосрочной валидации модель формирует сразу 12 месячных прогнозов для каждой станции по данным до конца декабря предыдущего года. Учебный пример содержит историю станции на начало года и 12 известных значений одного показателя за этот год. В обучение входят только завершённые годы с полным набором месячных целей для выбранного показателя. Факты проверяемого года сопоставляются с прогнозом для оценки и могут войти в обучение для следующего года. Для метрик и карт точности учитываются только пары с фактом. Отчёт также выводит MAE и число пар по каждому из 12 горизонтов.

Годовые средние DTR и суммы осадков в аналитике рассчитываются по полным 12-месячным рядам. Отдельный аналитический атлас показывает последний год валидации, 2020-й, при наличии пар с фактом. В текущих данных METEO_RU за 2020 год прогнозов нет из-за пропусков во входных данных конца 2019 года. Рабочую версию CRU и расчётные годы задаёт `code/kursach011_modules/project_settings.py`. Результаты сохраняются в `output011_modules/`. Годовые результаты записываются в `Validation_*.csv` с полем `Forecast_Mode=direct_annual`. Основной сценарий пересчитывает CSV прежнего режима. Для повторного использования CSV расчётов CRU проверяется версия источника.

В METEO_RU месячная сумма осадков рассчитывается при наличии значения за каждый календарный день. Для среднего DTR учитываются сутки с известными `Tmin` и `Tmax`. Допускается до пяти пропусков за месяц и до трёх подряд. Пригодность определяют отдельно для каждого показателя. Загрузчик проверяет наличие как минимум 3 650 полученных суточных строк на станцию до проверки пригодности отдельных суток.

Random Forest, KNN и MLP используют календарные лаги за 1, 2, 3 и 12 месяцев и средние за 3, 6 и 12 предыдущих месяцев. В годовом режиме лаги отсчитываются от января прогнозируемого года. Лаги и средние рассчитываются один раз на набор данных в каждом сценарии. Строки с пропущенными входами исключаются, а измеренные нули сохраняются. LSTM использует окно из 12 последовательных месяцев, которое в годовом режиме заканчивается декабрём. CSV сохраняют прогнозы и для месяцев с пропущенным фактом.

В месячном режиме LSTM для выпуска прогноза достаточно полной входной истории. В обучение входят предыдущие окна с известной целью, а в оценку — прогнозы с известным фактом.

Для каждой модели основной сценарий выводит число строк до и после отбора, число исключённых строк, число рассчитанных прогнозов и число пар с фактом, вошедших в оценку.

В основном сценарии, отчётах о прогнозе и сводке аналитики R2, MAE и RMSE выводятся на двух уровнях. В строке «Станция — месяц» каждое сопоставление факта и прогноза имеет одинаковый вес, а N показывает число пар. В строке «Региональные месячные средние» факт и прогноз сначала усредняются по одним и тем же станциям внутри каждого календарного месяца. Затем метрики рассчитываются по месячным средним, и N показывает число оценённых месяцев. MAE и RMSE выражены в миллиметрах для осадков и в °C для DTR. Основной сценарий выводит эти метрики и при повторном использовании совместимых CSV.

На сезонных картах и картах многолетней валидации оправдываемость — это процент доступных месячных пар «факт — прогноз» по станции, для которых абсолютная ошибка не превышает допуск. Рабочий допуск проекта для месячного DTR составляет 3 °C, а для месячной суммы осадков берётся большее из 5 мм и 20% фактической суммы. Порог 5 мм задаёт допуск при нулевых и малых осадках, а при суммах выше 25 мм допуск растёт пропорционально факту. Число пар на карте показывает, по скольким месяцам получена оценка.

Климатология — среднее значение для каждой станции и календарного месяца по доступной месячной истории с 1960 года. В месячном режиме берутся наблюдения до целевого месяца, а в годовом — до конца предыдущего декабря. В обоих случаях для целевого календарного месяца это значения из предыдущих лет. Нулевые осадки учитываются, а при отсутствии истории прогноз климатологии остаётся пустым.

В основной сводке, отчётах RF, KNN, MLP и LSTM и аналитическом `metrics_summary.txt` метрики каждой модели и климатологии вычисляются на общем наборе пар с известным фактом и обоими прогнозами. На региональном уровне сначала усредняются все три значения по одним и тем же станциям месяца. Столбец «Снижение MAE, %» показывает `100 × (1 − MAE модели / MAE климатологии)`. Отрицательное значение означает, что у модели ошибка выше. При нулевой MAE климатологии процент оставляют пустым. Для основной сводки с совместимыми CSV достаточно исходных месячных рядов, чтобы добавить сравнение без переобучения.

| Команда | Назначение |
| --- | --- |
| `python code/kursach011_map_meteo.py` | Карта станций по сохранённым координатам и ГИС-слоям. |
| `python code/kursach011_forecast_report.py` | Обучение моделей и отчёт о времени и точности расчётов. |
| `python code/kursach011_lstm.py` | Обучение LSTM и отчёты в `output011_modules/lstm/`. |
| `python code/kursach011_analytics.py` | Аналитические таблицы и карты по сохранённым результатам валидации. |
| `python code/kursach011_cross_correlation.py` | Сезонные корреляции месячных рядов METEO_RU с фактическими значениями и прогнозами CRU. |
| `python code/kursach011_eof.py` | EOF/PCA-анализ климатических рядов и результатов валидации. |
| `python code/kursach011_modules/tuning_lab.py` | Подбор параметров RF, KNN и MLP для обоих режимов. |
| `python code/kursach011_modules/mlp_check.py` | Короткая проверка лимита эпох MLP и разброса RF и MLP по seed. |

Основной сценарий сохраняет CSV валидации в `output011_modules/validation_results/csv_data/`. Их читают аналитический атлас, сезонный EOF и Excel со всеми компонентами EOF. Атлас пропускает карты рядов без значений в выбранном срезе. Для исторических рядов EOF используются исходные месячные значения.

Сравнение METEO_RU и CRU TS по сезонам использует совпадающие станции и месяцы из исходных рядов. Для сравнения METEO_RU с прогнозами нужны CSV валидации моделей CRU. В сводке указано число пар за каждый сезон и для каждой модели. Средняя корреляция по станциям и карты используют станции, у которых есть не менее 12 пар за сезон и определён коэффициент Пирсона.

EOF оценивает полноту каждой станции по календарю выбранного среза. Станция допускается при наличии не менее 90% месячных значений. Отдельные пропуски заполняются средним для соответствующего календарного месяца на той же станции. Даты, на которые у отобранных станций нет ни одного значения, в PCA не входят. Если для одного из календарных месяцев среза нет наблюдений ни в одном году, скрипт указывает причину пропуска среза.

### Подбор параметров

Для CRU TS 4.10 и METEO_RU параметры подбираются отдельно для осадков и DTR. Помесячный подбор использует выпуски с января 2022 по ноябрь 2023 включительно. Декабрь 2023 входит в оценку зимы 2023/24. Прямой годовой подбор использует выпуски за 1980–1989 годы. Для каждого выпуска модель обучается только на доступной к тому моменту истории. Годовая сводка помесячного прогноза охватывает 2024 год, оценка прямого годового прогноза — 1990–2020 годы.

В помесячном подборе исходный кандидат — встроенные `BEST_PARAMS`. В прямом годовом подборе исходным кандидатом служат действующие параметры. Выбирается комбинация с наименьшей MAE по региональным месячным средним. В каждом месяце все кандидаты оцениваются по одним и тем же станциям с известным фактом.

Чтобы подобрать параметры только для одного режима, добавьте `--mode monthly` или `--mode direct_annual`. Скрипт сохраняет результаты в `output011_modules/model_params.json`. Повторный подбор одного режима сохраняет параметры другого. Если помесячные параметры были получены на старом окне с декабрём 2023, запустите подбор с `--mode monthly` перед оценкой зимы. Основной сценарий и отчёт читают JSON автоматически. При отсутствии файла используются `BEST_PARAMS`. Основной сценарий пересчитывает CSV при изменении рабочих параметров.

В сравнительных Excel-таблицах `N_Stations` показывает число станций, по которым за месяц есть факт и прогнозы всех сравниваемых моделей. По этим станциям вычисляются все средние в строке. В исторических таблицах с фактом `N_Months` показывает число доступных месяцев за год. Годовой итог заполняется при 12 месяцах.

### Диагностика MLP

При обучении основной прогноз, валидация, отчёт и подбор сохраняют JSON в своих подкаталогах `diagnostics/mlp/` в корне проекта. Для каждого обучения указан выпуск, параметры, число эпох, предупреждения о сходимости и кривая обучающей ошибки. Сводка показывает, сколько обучений достигли лимита и сколько выдали предупреждение. При чтении готовых прогнозов нового обучения и диагностики нет.

`mlp_check.py` сравнивает действующие параметры MLP и лимиты 200 и 400 эпох с отключённой встроенной ранней остановкой. Для годового режима используются выпуски 1988 и 1989 годов для DTR на CRU TS 4.10 и осадков на METEO_RU. В помесячном режиме проверяется DTR на CRU за январь 2023 года. В годовом режиме действующие параметры RF и MLP дополнительно проверяются с seed 42, 43 и 44.

Результаты находятся в `diagnostics/mlp/short_check/both/`. В `comparison.csv` записаны обе MAE и размеры общей выборки по каждому запуску, в `seed_summary.csv` — сводка по seed для годовых выпусков, в `mlp_fits.json` — диагностика обучения. Для одного режима используйте `--mode monthly` или `--mode direct_annual`. Другую папку для этих файлов можно задать через `--output-dir`.

Исходная версия курсовой отмечена тегом `coursework-baseline`.
