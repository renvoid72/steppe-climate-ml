# Steppe Climate ML

Код курсовой по анализу суточной амплитуды температуры (DTR) и месячных осадков в степной зоне России. Проект сопоставляет ряды метеостанций с сеточными данными CRU TS, оценивает прогнозы Random Forest, KNN и MLP и формирует карты и отчёты.

## Структура

- [`code/kursach011.py`](code/kursach011.py) — основная точка входа для подготовки данных, прогнозирования, валидации и визуализации.
- [`code/kursach011_modules/`](code/kursach011_modules/) — загрузчики Meteostat и CRU TS, расчёт прогнозов, подбор параметров и построение карт.
- [`code/`](code/) — дополнительные скрипты для LSTM, EOF/PCA, корреляционного анализа и подготовки отчётов.

## Локальные данные

| Файлы | Содержимое |
| --- | --- |
| `meteo_ru/all_steppe_data.txt`, `meteo_ru/stations_coords.txt` | Суточные ряды и координаты метеостанций. Загрузчик получает ряды через [Meteostat](https://dev.meteostat.net/). |
| `meteo_ru/daily_sources.csv` | Исходные флаги `tmin_flag`, `tavg_flag`, `tmax_flag` и `prcp_flag` для каждой станции и даты из суточного TXT. |
| `meteo_ru/daily_source_summary.csv` | Годовые числа и доли модельных суточных осадков и DTR по флагам Meteostat. |
| `cru ceda/4.10/cru_aligned_data.csv` | Рабочие месячные ряды CRU TS 4.10 в точках станций за 1901–2025 годы. |
| `cru ceda/4.06/`, `cru ceda/4.06-reproduced/` | Эталон и воспроизведённая выгрузка CRU TS 4.06 за 1901–2020 годы. |
| `maps_countries/`, `maps_ecoregions/`, `maps_relief/` | Границы стран, экорегионы и рельеф для геообработки и построения карт. |

Данные и сгенерированные результаты хранятся локально. Правила исключения описаны в [`.gitignore`](.gitignore).

Рабочий ряд METEO_RU включает наблюдения и модельные оценки. Загрузчик запрашивает `model=True, flags=True`. Сводка считает модельным по классификации Meteostat значение с флагом, содержащим `G`. Для DTR учитываются оба экстремума, и достаточно `G` у одного из них. Meteostat 1.7.6 также использует `G` для кодов источника, которых нет в словаре библиотеки. Доля `ModeledSharePct` рассчитывается от всех доступных значений показателя, в том числе значений без флага. Они учитываются в отдельной графе `Unknown`. При сохранении загрузчик выводит общий итог в консоль.

## Установка на Windows

Установка проверена на 64-разрядной Windows с Python 3.14.0. Выполни команды в CMD из корня проекта.

```cmd
py -3.14 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
python -m pip check
```

Если `.venv` уже создана на Python 3.14, начни с её активации.

Для запуска [LSTM](code/kursach011_lstm.py) дополнительно установи сборку PyTorch для процессора в этом же окружении.

```cmd
python -m pip install torch==2.13.0 --index-url https://download.pytorch.org/whl/cpu
python -c "import torch; print(torch.__version__)"
```

Варианты сборок для других устройств перечислены в [инструкции PyTorch](https://pytorch.org/get-started/previous-versions/).

## Подготовка CRU TS 4.10

С установленными зависимостями и сохранённым `meteo_ru/stations_coords.txt` выполни из корня проекта.

```console
python code/prepare_cru.py
```

Скрипт скачивает архивы DTR и осадков по HTTPS, вырезает регион и собирает станционный CSV. Срез содержит 1 500 месяцев с января 1901-го по декабрь 2025-го. Центры ячеек лежат между 41,25 и 59,75° с. ш. и между 28,25 и 124,75° в. д. с шагом 0,5°. В каждом NetCDF сохранена его переменная `stn` с числом станций, участвовавших в интерполяции. [Официальный архив CRU TS 4.10](https://crudata.uea.ac.uk/cru/data/hrg/cru_ts_4.10/)

Результаты записываются в `cru ceda/4.10/`. Файл `station_grid.csv` содержит WMO, координаты станции и координаты выбранной ячейки. В `source.json` записаны версия, URL, период, границы и команда. При повторном запуске региональные NetCDF берутся из кэша. Если региональные файлы отсутствуют, скрипт вырежет срез из сохранённых `.gz` в `archives/`.

### Проверка на локальных данных

Обычные тесты используют небольшую временную сетку. Чтобы дополнительно сравнить локальные NetCDF и станционный CSV 4.10 с ручной выгрузкой 4.06 за 1901–2020 годы, положи `temp dtr full rus stepp.nc`, `precip full rus stepp.nc` и `cru_aligned_data.csv` в `cru ceda/4.06/`. Выполни в CMD из корня проекта.

```cmd
set "STEPPE_CHECK_LOCAL_CRU=1"
python -m unittest discover -s code -p "test_prepare_cru.py"
set "STEPPE_CHECK_LOCAL_CRU="
```

Сверка проверяет координаты, даты, единицы, маски пропусков, ключи `WMO + Year + Month` и привязку станций к сетке. Различия в значениях между выпусками выводятся в консоль.

CRU TS строит сеточные ряды с использованием станционных наблюдений. Совпадение с Meteostat само по себе не подтверждает независимую точность. [Метод CRU TS](https://crudata.uea.ac.uk/cru/data/hrg/gefaq2.htm)

## Запуск

Корень проекта определяется по расположению Python-файлов. Пути к данным и результатам вычисляются относительно этого корня, поэтому скрипты можно вызывать из другой рабочей папки, указав путь к скрипту.

Команды ниже выполняются из корня проекта в Python-окружении с установленными зависимостями.

```console
python code/kursach011.py
```

Основной сценарий готовит отсутствующие таблицы, обучает модели и строит карты. Для CRU и METEO_RU используются два режима.

| Режим | Период оценки | Горизонт | Переобучение |
| --- | --- | --- | --- |
| Стандартный прогноз | 2024 | Следующий месяц | Ежемесячно |
| Долгосрочная валидация | 1990–2020 | Январь–декабрь из одной точки выпуска | Ежегодно |

В долгосрочной валидации модель формирует сразу 12 месячных прогнозов для каждой станции по данным до конца декабря предыдущего года. Учебный пример содержит историю станции на начало года и 12 известных значений одного показателя за этот год. В обучение входят только завершённые годы с полным набором месячных целей для выбранного показателя. Факты проверяемого года сопоставляются с прогнозом для оценки и могут войти в обучение для следующего года. Для метрик и карт точности учитываются только пары с фактом. Отчёт также выводит MAE и число пар по каждому из 12 горизонтов.

Годовые средние DTR и суммы осадков в аналитике рассчитываются по полным 12-месячным рядам. Отдельный аналитический атлас показывает последний год валидации, 2020-й, при наличии пар с фактом. В текущих данных METEO_RU за 2020 год прогнозов нет из-за пропусков во входных данных конца 2019 года. Рабочую версию CRU и расчётные годы задаёт `code/kursach011_modules/project_settings.py`. Результаты сохраняются в `output011_modules/`. Годовые результаты записываются в `Validation_*.csv` с полем `Forecast_Mode=direct_annual`. Основной сценарий пересчитывает CSV прежнего режима. Для повторного использования CSV расчётов CRU проверяется версия источника.

В METEO_RU месячная сумма осадков рассчитывается при наличии значения за каждый календарный день. Для среднего DTR учитываются сутки с известными `Tmin` и `Tmax`. Допускается до пяти пропусков за месяц и до трёх подряд. Пригодность определяют отдельно для каждого показателя. Загрузчик проверяет наличие как минимум 3 650 полученных суточных строк на станцию до проверки пригодности отдельных суток.

Random Forest, KNN и MLP используют календарные лаги за 1, 2, 3 и 12 месяцев и средние за 3, 6 и 12 предыдущих месяцев. В годовом режиме лаги отсчитываются от января прогнозируемого года. Лаги и средние рассчитываются один раз на набор данных в каждом сценарии. Строки с пропущенными входами исключаются, а измеренные нули сохраняются. LSTM использует окно из 12 последовательных месяцев, которое в годовом режиме заканчивается декабрём. CSV сохраняют прогнозы и для месяцев с пропущенным фактом.

Для каждой модели основной сценарий выводит число строк до и после отбора, число исключённых строк, число рассчитанных прогнозов и число пар с фактом, вошедших в оценку.

| Команда | Назначение |
| --- | --- |
| `python code/kursach011_map_meteo.py` | Карта станций по сохранённым координатам и ГИС-слоям. |
| `python code/kursach011_forecast_report.py` | Обучение моделей и отчёт о времени и точности расчётов. |
| `python code/kursach011_lstm.py` | Обучение LSTM и отчёты в `output011_modules/lstm/`. |
| `python code/kursach011_analytics.py` | Аналитические таблицы и карты по сохранённым результатам валидации. |
| `python code/kursach011_cross_correlation.py` | Корреляционный анализ сохранённых результатов валидации. |
| `python code/kursach011_eof.py` | EOF/PCA-анализ климатических рядов и результатов валидации. |
| `python code/kursach011_modules/tuning_lab.py` | Подбор параметров моделей на 2021–2023 годах для обоих датасетов. |

Для постобработки нужны CSV валидации в `output011_modules/validation_results/csv_data/`. Их создаёт основной сценарий.
